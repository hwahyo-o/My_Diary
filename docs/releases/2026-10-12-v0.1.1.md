# My Diary v0.1.1 — Security & Stability Release

Release date: 2026-10-12

## Purpose

v0.1.1 consolidates the security, deployment, recovery, and transaction-entry hardening completed after the initial v0.1.0 MVP release. It does not introduce a Vault schema change.

## Hosting

- Canonical production: https://my-diary-2mw.pages.dev/
- Recovery / verification mirror: https://hwahyo-o.github.io/My_Diary/
- Vault schema: 1
- Service Worker release: `2026.10.12.2`

The two hosts intentionally use separate browser origins and do not share IndexedDB/Vault state automatically.

## Security and deployment hardening

- Protected `main` with pull-request and required CI gates.
- Cloudflare Pages established as canonical production.
- Real HTTP response security headers applied and verified.
- CSP permits only the WebAssembly capability required by Argon2id while continuing to reject general JavaScript `unsafe-eval`.
- RecoveryKey Base64URL decoding rejects non-canonical aliases.
- GitHub Actions are pinned to immutable commit SHAs.
- Deterministic `package-lock.json` + `npm ci` release pipeline.
- Dependency vulnerability audit in CI.
- Dependabot enabled for npm and GitHub Actions.
- Dependency Review enabled on pull requests.
- CodeQL JavaScript/TypeScript analysis enabled.
- SECURITY.md documents responsible vulnerability reporting.

## Runtime and recovery improvements

- 10–12 digit strong PIN policy with weak sequential/repeated patterns rejected.
- Improved weak-PIN feedback during onboarding.
- Encrypted `.vault` export verified in a live browser.
- Fresh-origin recovery flow validated manually by the user.
- Automated disaster-recovery round trip now verifies:
  - encrypted backup creation
  - fresh IndexedDB recovery
  - exact synthetic transaction restoration
  - new-PIN lock/unlock after recovery
- GitHub Pages is explicitly labeled as a recovery/verification mirror.
- Service Worker update messages now reject cross-origin senders before honoring `SKIP_WAITING`.

## Transaction-entry improvements

- Quick entry accepts common KRW forms including:
  - `3,000원`
  - `2500원`
  - `₩12,500`
- Transaction persistence is awaited before the form reports success.
- Save failures remain visible and no longer silently disappear.
